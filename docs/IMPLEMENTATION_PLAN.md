| 项目 | 内容 |
| --- | --- |
| 版本 | 1.0 |

| 依赖 | `PRD.md`、`TECHNICAL_DESIGN.md`、`UI_SPEC.md` |

## 1. 实施原则

- 按可独立验证的纵向切片交付。
- 新功能遵循测试先行：RED、GREEN、REFACTOR。
- 领域逻辑先于平台集成。
- 所有写接口具备幂等保护。
- 所有资源接口具备跨用户越权测试。
- 外部平台不确定性必须先通过小范围技术验证，不把假设扩散到业务代码。
- 每个阶段通过门禁后才进入依赖它的阶段。

## 2. 阶段 0：外部准备与风险验证

本阶段可以与后续本地领域设计并行，但它阻塞真机联调和上线。

### 2.1 账号与合规

- 注册或准备域名。
- 使用个人主体完成 ICP 备案。
- 准备 HTTPS 证书。
- 确认微信小程序服务类目。
- 申请待办提醒订阅消息模板。
- 申请 `wx.chooseLocation` 权限。
- 准备隐私保护指引、用户协议和隐私政策。

### 2.2 技术验证

- 真机验证 `wx.login` 和后端 `code2Session`。
- 真机验证订阅消息授权接受、拒绝和“保持选择”行为。
- 验证订阅消息模板字段长度和格式。
- 验证微信发送结果事件回调。
- 验证函数计算自定义域名和 HTTPS。
- 验证 Tablestore 的条件写、范围扫描和搜索索引延迟。
- 验证地点接口是否获批；失败时确认手动地点降级路径。

### 2.3 门禁 G0

- 登录链路有真实环境证据。
- 订阅消息的实际行为有真机证据。
- 地点能力获得明确结论。
- 自定义域名方案可用于微信合法域名。

## 4. 阶段 2：领域模型

### 4.1 测试先行

- 首页分组和排序。
- 每日、每周、每月重复。
- 月末回退。
- 闰年 2 月。
- 跨年。
- 提醒时间计算。
- 回收站到期。
- 字段长度和数量限制。

时间相关测试使用可注入时钟，不直接依赖系统当前时间。

### 4.2 实现

- 不可变领域类型。
- 状态迁移纯函数。
- 重复规则展开器。
- 时间和时区工具。
- 排序和筛选规则。
- 统一领域错误。

### 4.3 门禁 G2

- 领域测试全部通过。
- 重复和提醒模块分支覆盖率不低于 90%。
- 无微信或阿里云 SDK 依赖。

## 5. 阶段 3：阿里云开发环境

### 5.1 资源

- 函数计算 API 函数。
- 提醒定时函数。
- 维护定时函数。
- Tablestore 数据表和搜索索引。
- SLS Project 和 Logstore。
- KMS 凭据。
- RAM 最小权限角色。

### 5.2 基础设施管理

- 使用 Serverless Devs 或 Terraform 声明资源。
- 所有资源名称带环境前缀。
- 生产与非生产凭据完全隔离。
- 禁止在配置文件中提交 AccessKey。

### 5.3 验证

- API 函数可读取 KMS 凭据。
- API 函数可通过 RAM 角色访问 Tablestore。
- 定时函数按预期触发。
- 日志写入 SLS。
- 条件写和范围扫描符合预期。

### 5.4 门禁 G3

开发环境可以自动创建、验证和清理，不依赖隐藏的控制台手工设置。

## 6. 阶段 4：登录和会话

### 6.1 服务端

- 接收微信临时登录凭证。
- 调用 `code2Session`。
- 创建或识别用户。
- 签发随机服务端会话 Token。
- 只保存 Token 哈希。
- 支持会话轮换和注销。
- 对登录接口限流。

### 6.2 小程序端

- 封装 `wx.login`。
- 统一请求层。
- 会话安全存储。
- 401 时执行一次共享的重新登录。
- 重新登录失败时保留本地表单内容。

### 6.3 测试

- 正常登录。
- 无效或已使用凭证。
- 微信接口超时。
- 会话过期。
- 并发 401 只触发一次重新登录。
- 注销后旧会话不可使用。

### 6.4 门禁 G4

认证流程稳定，服务端不向客户端返回 `session_key` 或 `openid`。

### 7.1 服务端

- 收件箱自动创建。
- 清单 CRUD。
- 标签 CRUD。
- 待办 CRUD。
- 完成和撤销完成。
- 软删除到回收站。
- 字段和资源归属校验。
- 写接口幂等。
- 乐观锁冲突处理。

### 7.2 小程序端

- 待办首页。
- 快速创建。
- 详情和编辑。
- 清单页。
- 标签管理。
- 筛选。
- 手动地点。

### 7.3 测试

- 用户 A 无法读取或修改用户 B 的资源。
- 删除清单将任务移入收件箱。
- 删除标签只解除关联。
- 重复提交创建不会生成两条任务。
- 两个设备同时编辑时返回明确冲突。
- 首页分组和排序正确。

### 7.4 门禁 G5

从登录、创建、查看到完成的核心路径可端到端运行。

## 8. 阶段 6：UI 状态和地点降级

### 8.1 页面状态

- 加载。

### 8.2 地点

- 权限被拒时提供设置引导。
- 接口未获批时隐藏地图入口。
- 手动地点在所有情况下可用。

### 8.3 验证

- 系统字体放大。
- 长标题和多标签。
- 空列表和大量任务。
- 地图授权接受、拒绝和不可用。
- 核心操作不仅依赖滑动手势。

### 8.4 门禁 G6

已确认的页面规格全部具备加载、空、错误和降级状态。

### 9.2 小程序端

### 9.4 门禁 G7

重复规则测试矩阵全部通过，不产生重复实例。

## 10. 阶段 8：提醒

### 10.1 授权

- 创建或编辑时由用户点击触发订阅授权。
- 记录接受、拒绝、禁止和模板过滤结果。
- 重复任务显示补充授权提示。

### 10.2 调度

- 按分钟和分片扫描。
- 回看最多 5 分钟。
- 条件认领。
- 发送前检查任务状态和版本。
- 调用微信发送。
- 接收异步发送结果。
- 未知发送结果不自动重发。

### 10.3 测试

- 有效授权正常发送。
- 无授权进入跳过状态。
- 完成、删除或改期后不发送。
- 并发调度不重复发送。
- 网络超时进入未知状态。
- 微信明确拒绝时记录失败。
- 调度器暂停后恢复可以扫描遗漏窗口。

### 10.4 门禁 G8

真机证明提醒授权和实际送达符合产品文案；系统在故障重试时不重复骚扰用户。

## 11. 阶段 9：同步和离线写回

### 11.1 同步

- 增量同步游标。
- 任务、清单和标签变更。
- 删除墓碑。
- 分页和断点续传。

### 11.2 缓存

- 用户级缓存隔离。
- schema 版本。
- 容量控制和淘汰。
- 首屏先渲染缓存，再后台同步。
- 注销时清空缓存。

### 11.3 离线写回

- 离线可查看缓存。
- 离线创建、编辑、完成和删除进入待同步队列，顶部显示待同步数量。
- 恢复网络后自动回放同步。
- 实现离线写队列：变更排队、恢复后回放、乐观锁冲突处理。

### 11.4 门禁 G9

断网时不会产生伪成功修改；恢复网络后页面与服务端一致。

## 12. 阶段 10：回收站和注销

### 12.1 回收站

- 查询。
- 恢复。
- 永久删除。
- 清空。
- 30 天自动清理。
- 原清单不存在时恢复到收件箱。

### 12.2 注销

- 二次确认。
- 立即撤销全部会话。
- 立即阻止业务数据访问。
- 清除本地缓存。
- 7 天内物理删除业务数据。
- 清理任务可安全重入。

### 12.3 安全验证

- 清理任务先支持安全预览模式。
- 设置单次最大清理数量。
- 条件不符合时拒绝删除。
- 注销用户的全部业务表均有删除验证。

### 12.4 门禁 G10

注销后任何旧会话都不能访问原数据，清理任务有完整审计证据但不记录用户内容。

## 13. 阶段 11：可观测性和安全加固

### 13.1 可观测性

- 结构化日志。
- API 延迟和错误指标。
- 提醒调度延迟。
- 定时任务心跳。
- 微信接口错误。
- Tablestore 限流。
- 成本预算告警。

产品行为埋点：

- 首次创建流程开始和完成。
- 创建待办，不包含标题、备注、地点、标签或清单名称。
- 完成待办。
- 开启提醒。
- 创建清单和标签。
- 提醒接受、送达、失败和跳过。
- 活跃日期，用于计算 7 日活跃率。

埋点只携带事件名、时间、匿名用户标识和必要的枚举属性，不携带用户输入内容。

### 13.2 安全

- 仓库密钥扫描。
- 输入边界测试。
- 跨用户越权测试全覆盖。
- 日志脱敏抽查。
- 接口限流。
- 依赖漏洞扫描。
- 错误响应不泄露内部信息。

### 13.3 门禁 G11

- 安全审查 CRITICAL 和 HIGH 问题为零。
- 关键告警完成一次真实触发演练。

## 15. 提交拆分建议

实现开始后，每个逻辑阶段使用独立提交：

1. `chore: initialize miniprogram and serverless workspace`
2. `test: define todo domain behavior`
3. `feat: implement todo domain model`
4. `chore: provision development cloud resources`
5. `feat: add wechat authentication and sessions`
6. `feat: add lists tags and todo operations`
7. `feat: build core miniprogram screens`
8. `feat: add recurring todo generation`
9. `feat: add subscription reminder scheduling`
10. `feat: add sync and read-only offline cache`
11. `feat: add trash retention and account deletion`
12. `chore: add observability security and release gates`

测试先行阶段保留 RED、GREEN 和必要的重构证据，具体提交粒度遵循仓库当时的 TDD 工作流。

## 16. 实现启动条件

开始业务实现前至少需要：

- 本文和相关产品、技术、页面文档保持已确认状态。
- 明确开发使用的微信 AppID 和阿里云开发账号。
- 真实密钥有安全注入方式。
- 外部验证可以在隔离的开发环境执行。
- 备案、模板和地点申请已启动，或明确接受开发与审批并行。

本文仅定义实施顺序，不授权创建云资源、购买域名、提交备案或开始业务编码。
