---

## 1. 背景与目标

用户已经可以按日浏览安排。MVP 增加 **本周回顾**：对**允许 AI 的周**，基于该周任务事实调用国内 OpenAI 兼容模型，生成摘要与改进建议。

**用户价值**

- 快速回顾一周做了什么、完成得怎么样。
- 看到有依据的改进点，而不是空泛鸡汤。
- 无模型密钥时仍能看清统计与规则版改进，不阻塞使用。

**非目标（本 MVP）**

- 不自动修改、删除或重排任务。
- 不做微信订阅消息推送（Phase 2）。
- 不做周环比图表、团队周报、自由对话式 AI 助手。
- 不在「本周尚未到达 AI 开放时刻」时对本周调用模型。

## 2. 已确认产品决策

| 项 | 决定 |
| --- | --- |
| 周界 | 自然周：周一 00:00:00 – 周日 23:59:59.999，时区 `Asia/Shanghai` |
| 周标识 | `weekStart` = 该周周一的日期 `YYYY-MM-DD`（上海） |
| AI 开放时刻 | **周日 19:00（上海）起**可对本周生成 AI；此前本周 **只统计、不调模型** |
| 已结束周 | 任意时刻可对已完整结束的自然周生成 / 重新生成 AI |
| 默认落点 | 见 §3 |
| 模型 | Phase 1 主路径：国内 OpenAI 兼容 Chat Completions API |
| 降级 | 无 `LLM_API_KEY`（或等价配置）或调用失败 → 纯统计 + 规则改进 |
| 送模字段 | 标题、**备注**、清单名、优先级、dueAt/occurrenceDate、状态、是否提醒等事实字段 |
| 推送 | Phase 2 |

## 3. 默认展示与 AI 可用性

记 `now` 为上海当前时刻；「本周」为包含 `now` 的自然周；「上周」为上一自然周。

| 时间窗（上海） | 进入「本周回顾」默认周 | 本周 AI | 上周及更早 AI |
| --- | --- | --- | --- |
| 周一 00:00 – 周日 18:59 | 工作日（周一–周五）默认看 **本周统计**；周六默认可偏向上周完整周报（见下） | **不可用**（仅统计） | 可用 |
| 周日 19:00 – 23:59 | 默认 **本周**（可出 AI） | **可用**（调模型） | 可用 |
| 下周一及之后看「上周」 | 主推刚结束的上周完整周报 | 对本周：若仍未到周日 19:00 则不可用 | 上周可用 |

**落点细则（MVP）**

1. **周一–周五**：默认选中「本周」卡片 → 只展示本周迄今 **统计**；显著入口切换到「上周」看完整 AI 周报（若已生成或可生成）。
2. **周六 00:00 – 周日 18:59**：默认选中「上周」（完整周报）；可切换「本周」仅看统计。
3. **周日 19:00 – 周日结束**：默认选中「本周」；若尚无 AI 结果，展示「生成周报」；生成时 **调用模型 API**。
4. **任意已结束周**：可从周切换器选择历史周（MVP 至少支持「本周 / 上周」；更多历史周可只做上周+本周）。

**判定函数（实现口径）**

```text
aiAllowed(weekStart, now):
  weekEndExclusive = weekStart + 7 days  # 下周一 00:00 上海
  if now >= weekEndExclusive:
    return true   # 周已完整结束
  if now 落在 weekStart 对应周内
     and now.weekday == Sunday
     and now.time >= 19:00:
    return true   # 本周周日晚七点起
  return false
```

## 4. 信息架构与入口

- 路径：「我的」→「本周回顾」（新子页，非 Tab）。
- 不进入待办首页首屏，避免干扰「今天做什么」。

页面需支持：

- 周切换：至少「本周」「上周」。
- 在 AI 不可用时：明确文案，例如「本周周报将在周日 19:00 后生成」。
- 在 AI 可用且未生成：主按钮「生成周报」。
- 已生成：展示结果 +「重新生成」。
- 生成中：可离开页面；再次进入显示进度或已完成结果。

## 5. 页面信息结构

### 5.1 始终展示（不依赖 AI）

- 周标题：如「2026年8月18日 – 8月24日」+「本周迄今」或「完整周」标签。
- **统计块**（服务端聚合）：
  - 安排总数、已完成、未完成、逾期未完成（按该周口径）。
  - 高优先级完成率。
  - 最忙的一天（任务数最多的上海日期）。
  - 按清单 Top N（可选，MVP 建议有）。
- 空周：友好空态，不强制生成 AI。

### 5.2 仅当 `aiAllowed` 为真时展示

- **本周摘要**：3–6 句，基于事实。
- **需要改进**：3–5 条，每条含：类型、结论、依据（关联任务）、建议、严重度。
- **亮点**（可选）：0–3 条。
- 来源标记：`model`（模型名）或 `rules`（降级）。

### 5.3 交互

- 点击改进条关联任务 → 进入任务编辑（任务已删则提示）。
- 重新生成：覆盖该周正式结果（MVP 不保留多版本）。
- 复制周报纯文本（可选，MVP 建议有）。

## 6. 「本周日程」统计与送模口径

### 6.1 纳入该周的任务

满足任一即纳入：

1. `occurrenceDate` 落在该周；或
2. `dueAt` 的上海日历日落在该周；或
3. 无日期任务：在该周内被 **创建** 或 **完成**（用于统计「无日期」桶；送模时标记 `undated: true`）。

排除：`TRASHED`（回收站可不进正文，MVP 统计也可不计）。

### 6.2 送往模型的字段（每条任务）

- `id`、`title`、`notes`（备注，已确认送模）
- `status`（TODO / DONE）
- `priority`
- `listName`
- `dueAt` 或 `occurrenceDate`（上海日期/时间摘要即可）
- `dueHasTime`、`reminderEnabled`（若有）
- `completedAt`（若有，上海日）

### 6.3 服务端预聚合事实（给模型的 context，减少幻觉）

除任务列表外，固定附带：

- `weekStart`、`weekEnd`、`generatedAt`
- `stats`：完成数、未完成、逾期数、高优未完成列表 id、单日任务数峰值等
- `aiAllowed: true`（调用时必为真）

模型不得编造未提供的任务 id。

## 7. AI「需要改进」类型（固定枚举）

模型与规则降级共用同一枚举：

| `type` | 含义 | 规则降级触发示例（可调参） |
| --- | --- | --- |
| `OVERDUE_PILEUP` | 逾期堆积 | 逾期未完成 ≥ 3 |
| `HIGH_PRIORITY_OPEN` | 高优未闭环 | 存在 HIGH 且未完成/逾期 |
| `DAY_OVERLOAD` | 单日过载 | 某日任务数 ≥ 8 |
| `UNDATED_PILEUP` | 无日期堆积 | 无日期未完成 ≥ 5 |
| `REPEAT_MISS` | 重复任务多次未完成 | 同 series 本周 ≥ 2 次未完成 |
| `REMINDER_INEFFECTIVE` | 提醒未促成完成 | 开启提醒且仍逾期/未完成 |

输出每条：

```json
{
  "type": "HIGH_PRIORITY_OPEN",
  "severity": "high",
  "title": "一句话结论",
  "rationale": "依据说明",
  "suggestion": "可执行建议",
  "taskIds": ["..."]
}
```

约束：

- `taskIds` 必须属于本周事实列表。
- 条数上限 5；无依据则不输出该条。
- 语气：教练式，不指责用户。

## 8. 模型调用与降级

### 8.1 主路径

1. 校验登录与 `aiAllowed(weekStart, now)`；不满足则 `403`/`400`，业务码如 `WEEKLY_REVIEW_AI_NOT_AVAILABLE`。
2. 聚合该周任务与 `stats`。
3. 若未配置 LLM：走 §8.2。
4. 调用国内 OpenAI 兼容接口（如 DashScope / DeepSeek 等兼容 `chat/completions`）：
   - 系统提示：角色、枚举、JSON Schema、禁止编造。
   - 用户内容：压缩后的事实 JSON（含备注）。
5. 严格 JSON 解析与 Schema 校验；失败可重试 1 次，再降级规则。
6. 写入 `weekly_reviews`，`source = model`。

### 8.2 降级路径（`source = rules`）

- 统计块与主路径相同。
- 摘要：模板句拼接统计（非模型）。
- 改进：仅按 §7 规则表生成；无命中则改进列表为空并说明「本周节奏正常」。

### 8.3 限流与成本

- 每用户每自然周：成功生成 ≤ 5 次（含重新生成）；超出返回友好限流。
- 记录：`userId`、`weekStart`、耗时、token（若有）、成功/失败；**日志不落完整备注正文**（可截断 hash 或仅长度）。

### 8.4 配置（环境变量，名称可在实现时微调）

- `LLM_API_BASE_URL`
- `LLM_API_KEY`
- `LLM_MODEL`
- 可选：`LLM_TIMEOUT_MS`、`WEEKLY_REVIEW_MAX_TASKS`（送模任务上限，超出按优先级+逾期截断并注明）

## 9. 数据与 API（草案）

### 9.1 表 `weekly_reviews`

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `user_id` | 用户 |
| `week_start` | 周一 `YYYY-MM-DD` |
| `status` | `ready` / `failed`（MVP 同步生成则可无 `generating`；若异步再补） |
| `source` | `model` / `rules` |
| `stats` | JSON |
| `summary` | 文本 |
| `improvements` | JSON 数组 |
| `highlights` | JSON 数组 |
| `model` | 模型名，可空 |
| `error_code` | 失败时 |
| `created_at` / `updated_at` | 时间 |

唯一约束：`(user_id, week_start)`。重新生成覆盖同行。

注销账号时随用户数据删除。

### 9.2 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/v1/weekly-reviews/current` | 按默认落点规则返回应展示的周 + 统计；若已有 review 一并返回；标注 `aiAllowed` |
| `GET` | `/v1/weekly-reviews?weekStart=` | 查询指定周统计 + 已有 review |
| `POST` | `/v1/weekly-reviews/generate` | body: `{ weekStart }`；仅当 `aiAllowed`；幂等键可用 `X-Request-Id` |

`GET` 在 AI 未开放时仍返回统计与 `aiAllowed: false`，不返回伪造的 AI 摘要。

## 11. Phase 1 / Phase 2 边界

### Phase 1（本文 MVP）

- 文档口径（本文）落地后的服务端聚合 + 生成接口。
- 国内兼容 API 主路径 + 规则降级。
- 「我的」入口 + 回顾页（本周/上周）。
- 周日 19:00 AI 门控；备注送模。
- 限流、落库、基础测试与配置说明。
- **打开页面时**若已允许 AI 且无结果，由用户点击生成（可不做定时任务）。

### Phase 2（明确不做进 MVP）

- 周日约 19:00 服务端定时预生成。
- 微信订阅消息「周报已生成」。
- 更多历史周浏览、反馈「有用/不准」、一键根据建议创建跟进任务。

## 12. 验收标准（MVP）

1. 周一至周日 18:59，对本周调用生成接口被拒绝，页面无 AI 摘要块，统计正常。
2. 周日 19:00 后（测试可注入 `now`），对本周生成成功：有摘要与改进（或规则降级结果），`source` 正确。
3. 对上周在任意工作日可生成/查看完整周报。
4. 配置有效 Key 时走模型；去掉 Key 后走规则降级且页面可用。
5. 送模 payload 含备注字段；日志无完整备注明文。
6. 改进项 `taskIds` 均存在于该周任务集；点击可打开仍存在的任务。
7. 同一周重复生成覆盖旧结果；超过限流次数有友好提示。
8. 用户注销后该用户 `weekly_reviews` 不可再访问并被清理策略覆盖。

## 13. 测试要点

- 单元：`aiAllowed` 边界（周日 18:59:59 / 19:00:00、下周一 00:00）。
- 单元：周任务归属（dueAt、occurrenceDate、无日期创建/完成）。
- 单元：规则降级触发与条数上限。
- 集成：generate 在未开放时 4xx；开放后落库；无 Key 降级。
- 契约：模型返回非法 JSON / 伪造 taskId 时校验失败并降级或报错（选定一种并测稳）。

## 14. 开放实现细节（不阻塞定稿）

以下实现时可定，不改变产品语义：

- 同步 HTTP 生成 vs 短轮询异步（若模型耗时 > 15s 建议异步）。

- 送模任务截断策略的精确排序。
